# ゲームルール

ルールはすべて `src/room/GameEngine.ts` に集約する。Room Durable Object は判定結果を配信するだけで、ルールを持たない。

## 出題形式

問題セットごとに `mode` で選ぶ。全問が同じ形式になる。

| mode | 回答 | 判定 |
|---|---|---|
| `anagram`（既定） | スマホのフリーテキスト | サーバーが正規化して自動判定 |
| `buzzer` | 早押しボタン → 口頭 | GM が正解・不正解を判定 |

以下の「制限時間」「スコア」「お手付き」はアナグラムの規則。早押しは [早押しモード](#早押しモード) を参照。

## ゲームの流れ

ルームのフェーズは `lobby` → `intro` → `question` → `questionResult` → （次の問題があれば `question` へ）… → `finalResult` → `lobby` と遷移する。

1. GM が PC でルームを作成する。ルームコードと QR コードが表示される。
2. 参加者は QR を読み取り、ニックネームを入力して待機画面へ。GM 画面の参加者一覧がリアルタイムに更新される。
3. GM が問題セットを選び「開始する」を押すと、GM 画面にタイトルスライド（企画名・表紙・全n問・制限時間・お手付き上限）が表示される。続けて問題セットの説明スライドを「次へ」で順に表示し、最後の「第1問へ」で1問目が全員の画面に表示される。参加者の画面はその間「まもなく開始します」のまま。スライドの進行もルームの状態なので、GM がブラウザを再読み込みしても同じスライドに戻る。接続中の参加者が0名のときは開始できない。
4. 参加者が回答を送信する。
   - 正解: GM 画面に「〇〇さんが正解しました！」のポップアップと紙吹雪。本人には「正解！（n番目）」。
   - 不正解: 本人に「不正解（残りn回）」。
5. 次のいずれかで問題が終了し、正解と現在の順位を全員に表示する。
   - 制限時間終了（サーバーの Alarm で確定）
   - 接続中の参加者全員が正解またはお手付き上限に到達
   - GM の手動「締切」
6. GM が「次の問題へ」で次の問題へ。最終問題の後は「最終結果へ」で最終順位表を表示する。
7. GM は「もう1ゲーム」でロビーに戻り、同じルームで続けて別の問題セットを開始できる。開始時に「前のゲームのスコアを通算する」を選べる。通算しない場合は開始時に全員 0 点に戻る。
8. GM は出題中・結果表示中でも「ロビーへ戻る」でゲームを中断できる。スコアは保持される。

開始は `lobby` か `finalResult` のときだけ受け付ける。

## 制限時間

問題セット単位で設定し、問題ごとに上書きできる。

| モード | 動作 |
|---|---|
| `fixed`（固定カウントダウン） | 出題と同時に `timerSeconds` 秒のカウントダウンを開始し、0秒で締切 |
| `afterFirstCorrect`（正解者トリガー） | 出題時は無制限。最初の正解者が出た瞬間に `timerSeconds` 秒のカウントダウンを開始 |
| `none`（なし） | GM が手動で「締切」を押すまで受付 |

いずれのモードでも GM は手動で締切できる。締切時刻はサーバーが決め、クライアントは表示にだけ使う（[通信プロトコル](protocol.md#タイマー)）。

## スコア

- 正解1問につき基本点 `basePoints`（既定 100）。
- 正解順ボーナス `rankBonus`（既定 `[50, 30, 10]`）: 正解した順に配列の値を加算する。配列の範囲外は 0。空配列でボーナスなし。
- 不正解ペナルティ `wrongPenalty`（既定 0）: 不正解1回ごとに減点する。
- 順位は得点の降順。同点は同順位とし、次の順位は飛ぶ（1, 1, 3）。同点内の並びは入室順。

## お手付き（不正解回数の上限）

- `maxAttempts`（既定 3）: 1問あたりの回答回数上限。`null` で無制限。
- 上限到達でその問題は回答不可となり、本人画面に表示する。
- 正解後はその問題に再回答できない。

## 設定の優先順位

問題ごとに実際に効く設定は、次の順で上書きして決まる。

1. 既定値（`timerMode: fixed`, `timerSeconds: 30`, `basePoints: 100`, `rankBonus: [50,30,10]`, `wrongPenalty: 0`, `maxAttempts: 3`）
2. 問題セットの `settings`
3. 問題の `overrides`
4. GM がゲーム中に上書きしたライブ設定（全問共通の設定と同じ6項目）

ライブ設定はルームに保持され、ゲームをまたいで有効であり続ける。GM は上書き全体を送り直す形で変更し、空にすれば問題セットの設定に戻る。

出題中に変更した場合も現在の問題にすぐ効く。

- `timerMode` を変えると、現在の問題の締切を合わせ直す。`none` なら締切を消す。`fixed` なら締切が無ければ「今＋`timerSeconds`」で開始する。`afterFirstCorrect` なら締切が無く、すでに正解者がいれば「今＋`timerSeconds`」で開始し、いなければ最初の正解を待つ。すでに動いている締切は動かさない
- `timerSeconds` だけを変えた場合、動いている締切はそのままで、次に締切を決めるときから使う
- `maxAttempts` / `wrongPenalty` / `basePoints` / `rankBonus` は以降の回答から効く。すでに加減した点数は変えず、問題結果にも回答時の点数を出す

## 日本語フリーテキスト回答の判定

- 問題ごとに正解候補を複数登録できる（例: 「りんご」「リンゴ」「林檎」）。
- 判定前に回答と正解候補の両方を正規化し、完全一致すれば正解。
  1. Unicode NFKC（全角英数→半角、半角カナ→全角カナ、結合濁点→合成済み）
  2. 前後の空白（全角スペース含む）を除去
  3. カタカナをひらがなに変換
  4. 長音・ハイフン類（`-ー－‐‑‒–—−`）を「ー」に統一
- 正規化後に空文字になった回答は不正解。
- アナグラム問題では `prompt` にシャッフル済み文字列、`answers` に元の言葉を登録する。編集画面の「生成」は正解候補の先頭からシャッフル文字列を作り、元の文字列とは必ず異なる結果を返す。

## 回答の受付

- 回答の到着順と時刻はサーバー（Durable Object）受信時刻を使い、クライアントの時計に依存しない。
- 締切後に届いた回答は「時間切れ」として拒否する。
- 以下は拒否し、スコアを変更しない: 出題中でない、締切後、すでに正解済み、お手付き上限到達、GM からの回答。

## 参加者

- ニックネームは前後空白を除いた先頭20文字。空は拒否する。
- 同名の参加者がいる場合、後から入った人を「名前 (2)」「名前 (3)」… とする。
- 接続断（スリープ等）しても、同じブラウザで再接続すればニックネームとスコアを引き継ぐ。端末に発行した参加者トークンで識別する。
- 「全員が回答し終えた」判定は接続中の参加者だけを対象にする。切断中の参加者は待たない。

## GM のゲーム中操作

GM 画面の「管理」パネルから、どのフェーズ（タイトル・説明スライド表示中を含む）でも次を行える。

| 操作 | 内容 |
|---|---|
| 設定の上書き | 制限秒数・お手付き上限（無制限可）・不正解ペナルティ。早押しでは読み上げ速度。[設定の優先順位](#設定の優先順位)の最上位 |
| スコア調整 | 参加者ごとに任意の点数を加減する。順位表に即時反映 |
| キック | 参加者をルームから削除し、その回答とトークンも消す。本人の画面は参加画面に戻り「退出されました」と表示する。同じ端末から入り直すと新規参加になる。キックで残りの全員が回答済みになれば問題を自動で締め切る |
| 途中参加 | 参加用 QR をゲーム中に表示する。途中参加者は 0 点から始まり、現在の問題にそのまま回答できる |

## 早押しモード

出題中の流れは `question` フェーズの中で `BuzzerState` が持つ（[データモデル](data-model.md#ルーム状態durable-object-内)）。

1. 問題を開くと「読み上げ待ち」（`ready`）。GM が「読み上げ開始」を押すと、問題文が GM 画面に `charsPerSecond`（既定 6 文字/秒）で一文字ずつ表示される（`reading`）。参加者のスマホには問題文を出さない
2. 参加者が早押しボタンを押すと、サーバー受信時刻で表示位置が確定して止まる（`paused`）。押した人はサーバー受信順にキューに並び、先頭が回答中。読み上げが止まっている間も押してキューの末尾に並べる
3. 回答者は口頭で答え、GM が「正解」「不正解」で判定する。判定には対象の参加者 ID を添え、回答中の人と違えば（二度押しで次の人に回った後など）拒否する
   - 正解: `basePoints` を加点し、その問題は終了（問題結果へ）。正解順ボーナスは使わない
   - 不正解: `wrongPenalty` を減点し、その人はこの問題でもう押せない。キューに次の人がいればその人が回答中になる。いなければ止まった位置から読み上げを再開する
4. 全文を表示し終えても自動では締め切らない。GM が「締切」を押すまで早押しを受け付ける
5. 接続中の参加者全員が押せなくなり、キューが空になったら自動で締め切る

- 回答中の人をキックすると、減点せずに次の人へ回す（いなければ再開）。キューの途中の人をキックするとキューから消えるだけ
- 切断は何も変えない。回答中の人が切断しても GM の判定で進める
- 表示済み文字数は「止めた位置 ＋ (今 − 再開時刻) × 文字/秒」でサーバーとクライアントが同じ式で計算する（`src/shared/buzzer.ts`）。GM がライブ設定で `charsPerSecond` を変えると、その時点の位置を起点に取り直すので表示が飛ばない
- `timerMode` / `timerSeconds` / `rankBonus` / `maxAttempts` は効かない。締切は常に無し
- 文字回答（`answer`）は `not_in_question` で拒否する
