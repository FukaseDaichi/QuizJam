# 早押しの判定用端末（GM の手元スマホ）

## 目的

早押しの GM 画面はプロジェクターに映すので、出題中に答えを出せない。GM は答えを覚えるか紙で持つしかなく、別解や「この答えは不正解」といった判定の決まりも手元に無い。
GM が手元のスマホで「判定用画面」を開き、答え・別解・判定メモ・回答中の人を見ながら、その場で正解・不正解を押せるようにする。

## 目標

- 出題中、判定用端末にだけ今の問題の答え（正解候補すべて）と判定メモを出す
- 判定用端末から「正解」「不正解」を押せる（GM 画面のボタンもそのまま残す）
- スマホは GM 画面に出す使い捨ての QR でつなぐ。QR は最初に読み取った 1 台だけが使え、使われたら画面から消える
- 問題に「判定メモ」を書けるようにする（押しどころ・別解の扱い・不正解にする答えなど）

## しないこと

- 判定用端末からの進行（読み上げ開始・締切・次へ・管理）。進行は今までどおり GM の PC で行う
- 判定の取り消し（誤って押したときは今までどおり管理パネルの点数調整で直す。別の変更で扱う）
- アナグラムモードでの判定用端末（自動判定なので要らない）
- 判定用端末で効果音・問読み音声を鳴らすこと（音は GM の PC から）
- 判定用端末を複数台つなぐこと

## 失敗とみなすこと

- 答え・判定メモが、プロジェクターの画面や参加者の画面・WebSocket の通信に一度でも出る
  - 守る範囲は画面と通信まで（ユーザーの決定）。認証なしの `GET /api/question-sets/:id` を自分で叩けばセット全体（答え・判定メモを含む）が取れるが、今回は塞がない
- 投影された QR を参加者が後から読み取って判定用端末になれる
- 判定用端末から、判定以外の GM 操作ができる

## 方式の比較（決定: A）

| 方式 | 内容 | 判断 |
|---|---|---|
| **A. 使い捨て QR** | GM 画面に一度だけ使えるペアリング用の QR を出し、読み取った端末に判定専用のトークンを渡す | **採用**。会場でスマホをかざすだけでつながる。読み取られたら無効になり、権限も判定だけに絞る |
| B. リンクを自分で送る | 「判定用リンクをコピー」を押し、LINE や AirDrop で自分のスマホへ送る | 画面に何も映らず最も安全だが、毎回送る手間がかかる |
| C. 同じ PC で 2 画面 | PC の手元画面に答え付き、プロジェクターに答え無しを出す | 端末は 1 台で済むが、拡張ディスプレイの設定が要り、ミラーリングの事故で答えが映る |

A に残るリスク: GM より先に参加者が QR を読み取ると、その人が判定用端末になる。GM 画面に「判定端末: 接続中」と出るので、自分のスマホがつながっていなければ QR を出し直して取り戻せる（出し直すと前の端末は切れる）。

## 決めたこと（ユーザーの決定）

- つなぎ方は A（使い捨て QR）
- GM 画面の「正解」「不正解」ボタンは残す

## 設計（実装者の判断として提案。レビューで直してよい）

### 役割とトークン

- WebSocket の接続に 3 つ目の役割 `judge` を足す（`Attachment = { role: "gm" } | { role: "judge" } | { role: "player"; participantId }`）。タグは `role:judge`
- `judge` が送れるのは `judge` メッセージだけ。それ以外の GM 操作・`answer`・`buzz` は `forbidden`
- 判定用トークンはルームに 1 つ。Room の kv に `judgeToken` として保存する。新しく発行すると前のトークンは無効になり、つながっている `role:judge` のソケットは閉じる（close code 4001 など。判定用画面は「別の端末がつながりました」と出す）
- 前の端末が切れるのは、新しい QR が**読み取られて**トークンを発行した時（QR を出しただけでは切らない。GM が誤って QR を開いても今の端末はそのまま）〔実装者の判断〕
- `pickGenre` など「GM か参加者か」で分けている処理では、`judge` は GM として扱わない（`forbidden`）〔実装者の判断〕

### ペアリング（使い捨て QR）

1. GM が管理パネル（または早押しの出題画面の隅）の「判定用スマホをつなぐ」を押す → GM が `issueJudgePairing` を送る
2. Room は推測できないペアリングコード（128 bit 以上のランダム）を作り、kv に有効期限（発行から 5 分）付きで保存する。前のペアリングコードは捨てる。GM にだけ `judgePairing { url, expiresAt }` を返す
3. GM 画面は QR（`/judge/:roomCode#pair=<コード>`。コードはフラグメントに入れてサーバーのアクセスログに残さない）を大きめのモーダルで出す。期限切れか、接続されたら閉じる。手で閉じることもできる
4. スマホの判定用画面はフラグメントからコードを読み、`POST /api/rooms/:code/judge-pair { pairCode }` を送る。Room は、コードが一致して期限内ならコードを消して（1 回しか使えない）新しい `judgeToken` を作って返す。一致しない・期限切れは 403
5. スマホは `judgeToken` を localStorage に保存し、URL からフラグメントを消して（`history.replaceState`）、`/ws/room/:code?token=<judgeToken>` に接続する。再読み込みや画面ロック後の再接続は保存したトークンで行う
6. 接続を受けたら Room は GM に判定端末の接続状態（`judgeConnected: boolean`）を伝える。GM 画面には「判定端末: 接続中／未接続」を小さく出す

### 判定用端末に送る内容

- `state` は役割 `judge` で送る。参加者向けと同じく問題文・音声は送らず、早押しの状態（`buzzer`: 回答中の人・待ち行列・表示済み文字数）と、今の問題の判定情報を送る
- 判定情報 `JudgeView = { questionNumber, total, genre?, prompt, answers: string[], judgeNote?: string, revealAtMs?: number[] }`。`revealAtMs` は音声付きの問題で、読まれた位置を GM 画面と同じ計算で出すため（音声そのものは送らない）。画像だけの問題（`prompt` が空）は問題文の欄を出さない〔実装者の判断〕。`prompt` は全文（判定用端末は GM 側の人が持つ前提なので見せてよい。どこまで読まれたかを示すために使う）
- `questionStarted` のたびに判定用端末へ `judgeInfo { judge: JudgeView }` を送る。GM・参加者には送らない
- 答えを GM の `QuestionView` には足さない（GM 画面の通信に答えを載せない）

### 判定用画面（スマホ縦、`/judge/:code`）

```
┌──────────────────────┐
│ 第12問 / 70   麻雀の点数計算 │
│ 答え  7700点                │
│ 判定メモ                     │
│  8000点は不正解（切り上げ…）  │
│ 問題文（読まれた所まで濃く）   │
│ ──────────────────────── │
│ 回答中: たろう              │
│ 次: はなこ → じろう           │
│ ┌────────┐ ┌────────┐ │
│ │  正解  │ │ 不正解 │ │
│ └────────┘ └────────┘ │
└──────────────────────┘
```

- 答えは最初の 1 つを大きく、残り（別解）を小さく並べる
- 「正解」「不正解」は回答中の人がいる（`paused`）ときだけ押せる。判定には回答中の参加者 ID を添える（今の `judge` メッセージと同じ。二度押しで次の人まで判定されない）
- 誤タップを防ぐため、ボタンは画面下に大きく、2 つの間を空ける
- 出題中でないとき（タイトル・結果・ジャンル選択など）は「次の問題を待っています」と、次に出る問題の情報は出さない
- アナグラムのセットでは「このセットは自動判定です」とだけ出す
- 判定用画面を開いたまま画面がスリープしても、復帰したら再接続して今の状態を受け取る（既存の再接続の仕組みを使う）

### 判定メモ（問題セット）

- `Question` に `judgeNote?: string` を足す（前後の空白を除いて 1〜500 文字、複数行可）。早押しでだけ使う
- 管理画面の問題スライドの右パネルに、早押しのときだけ「判定メモ（GM の判定用端末にだけ出る）」の複数行入力を足す
- 検証（`validateQuestionSet`）に長さの確認を足す
- 判定メモは参加者・GM 画面には送らない。問題結果でも出さない

## 実装者に任せること

- ペアリングの期限（5 分）とコードの長さの具体値
- QR モーダルの見た目と置き場所（管理パネルの中が第一案）
- 判定用画面の細かい見た目（デザインガイド `docs/design-guide.md` に合わせる）
- close code の具体値
