# ジャンル選択つき早押し（大自然クイズ）設計

## ねらい

「大自然クイズ」を QuizJam で遊べるようにする。14 ジャンル前後 × 各 5 問ほどの早押しクイズで、正解した人が次のジャンルを指定する。参加者は最初に得意ジャンルを 2 つ申告し、得意でないジャンルで正解すると点数が 2 倍になる。

正解者が場の流れを握ることと、得意を避けて高得点を狙う駆け引きが、この企画の中身である。

## ゴール

- 早押しの問題セットで、問題にジャンルを付けられる
- 第 1 問のジャンルはランダム。以降は直前の正解者がジャンルを指定し、そのジャンルの未出題の問題からランダムに 1 問が出る
- 誰も正解しなかったら、次のジャンルはランダム
- 問題が尽きたジャンルは選べない
- 全問を出し切るか、GM が途中で終了したら最終結果になる
- 参加者は得意ジャンルを 2 つ選ぶ。得意ジャンル以外の問題に正解すると加点が 2 倍
- 出題中、GM 画面にその問題のジャンルが出る
- 読み上げは今の早押しと同じく、GM の「読み上げ開始」で始まる

## やらないこと

- 大自然クイズの問題・問読み音声そのものの作成（問題セットは別途用意する）
- ジャンル決定のルーレットなどの演出（決まったジャンルを表示するだけ）
- 得意ジャンルの選び直し
- ジャンルごとの設定（配点や読み上げ速度）
- アナグラム形式でのジャンル

## 避けたいこと

- ジャンルの無い既存の早押しセット（saru・movie）とアナグラムの動きが変わること
- 得意ジャンルを選ばないほうが得になること
- 正解者が切断・放置したときにゲームが止まること

## 制約

- ルールは `src/room/GameEngine.ts` に集約する。Room Durable Object は結果を配るだけ
- 状態はスナップショットで保存・復元する。GM が再読み込みしても同じ場面に戻る。古いスナップショットも復元できる
- 開きっぱなしの古いクライアントが新しいメッセージを受け取っても壊れない（今の `isKnownServerMessage` の扱いに従う）
- 実装と同じコミット群で `docs/` 直下の設計書を更新し、この文書は完了時に削除する（`docs/AGENTS.md`）

## 検討した作り方

| 案 | 内容 | 良い点 | 悪い点 |
|---|---|---|---|
| 1. 早押しを拡張し、フェーズ「ジャンル選択」を足す（採用） | 問題にジャンルを持たせ、問題結果と出題のあいだに選択の場面を置く | 読み上げ・音声・判定をそのまま使える。再読み込みで「誰が選んでいる途中か」に戻れる。正解発表と選択が別の場面になる | フェーズが増え、GM・参加者画面と設計書の手直しが広い |
| 2. 問題結果の画面の中で選ぶ | フェーズを増やさない | 進行の変更が小さい | GM 画面に正解・得点とジャンル一覧が同居して窮屈。正解を見せ切る前に次を選べる |
| 3. 別の形式として新設 | 早押しに触らない | 既存への影響なし | 読み上げと音声合わせが二重になる |

案 1 を採用する（ユーザーの決定）。

## 決まっていること（ユーザーの決定）

- ジャンルの指定は、正解者が自分のスマホで選ぶ。GM 画面からも代わりに選べる
- 得意ジャンルを選び終えるまで、その参加者は早押しできない。自動で割り当てない
- 出題中に得意ジャンルを決定した人は次の問題から押せる。問題が尽きたジャンルは得意に選べない
- 得意ジャンルと「×2」は会場のスクリーンに出す
- 誰も正解しなかったら次のジャンルはランダム
- 問題が尽きたジャンルは選べない
- 終わりは全問出題か GM の途中終了

## 設計（ここから下は設計者の判断。違っていれば直す）

### 問題セット

- `Question.genre?: string` を足す。前後の空白を除いて 1〜30 文字
- **ジャンル制**のセット ＝ `mode: "buzzer"` で、全問に `genre` があるセット。専用の `mode` は増やさない
- ジャンルの一覧と並びは、問題の並びで最初に現れた順から導く。セット側に一覧は持たない（JSON を手で書きやすくするため）
- バリデーション
  - `genre` は早押しでだけ保存し、ほかのモードでは落とす（`audio` と同じ扱い）
  - 早押しで、`genre` のある問題と無い問題が混ざっていたら拒否する
  - ジャンル制ではジャンルが 3 種類以上必要（得意 2 つを選んでも 2 倍になるジャンルが残るように）
- quiz-tts の `publish` は既存の問題に `audio` を足して書き戻すだけなので、`genre` は落ちない（確認済み。変更不要）

### ルーム状態

- フェーズに `genreSelect` を足す: `… → questionResult → genreSelect → question → …`
- `EngineState` に足すもの
  - `asked: number[]` … 出題済みの問題の位置（出題順）。`currentIndex` は今の問題の位置で、並び順どおりには進まない
  - `genrePick: { pickerId: string } | null` … `genreSelect` のあいだ、選ぶ人
- `Participant.specialties?: string[]` … 得意ジャンル（2 つ）。未選択は無し
- ゲーム開始（`start`）で `asked` と全員の `specialties` を消す。スコアを通算する場合も、得意ジャンルは選び直す
- 古いスナップショットに `asked` が無ければ `[]`、`genrePick` が無ければ `null`
- 「第 n 問」の n は出題した数（`asked.length`）。全 m 問は問題数。ジャンル制でないセットでは今までどおり並び順

### 進行

1. **開始〜説明スライド**: 今までどおり。この間に参加者は得意ジャンルを選ぶ
2. **第 1 問**: 最後のスライドで「第 1 問へ」を押すと、サーバーが残りのあるジャンルからランダムに 1 つ、その中の未出題からランダムに 1 問を選び、読み上げ待ち（`ready`）で開く
3. **出題〜判定**: 今の早押しと同じ
4. **問題結果 →「次へ」**
   - 未出題が無ければ最終結果へ
   - その問題に正解者がいて、まだルームにいれば、その人を選ぶ人にして `genreSelect` へ
   - 正解者がいない（締切・全員不正解・正解者がキック済み）なら、ランダムで次の問題を開く
   - 残りのあるジャンルが 1 つだけなら、選択を飛ばしてそのジャンルから開く
5. **ジャンル選択**: 選ぶ人のスマホか GM 画面でジャンルが選ばれると、そのジャンルの未出題からランダムに 1 問を読み上げ待ちで開く
   - 残り 0 のジャンル、存在しないジャンル、選ぶ人以外の参加者からの指定は拒否する
   - GM は任意のジャンルを選べるほか、「ランダムで決める」も押せる
   - 選ぶ人がキックされたら、ランダムで次の問題を開く。切断しただけなら待ち、GM が代わりに選べる
6. **途中終了**: GM の「ここで終了」で、出題中・問題結果・ジャンル選択のどこからでも最終結果へ進む。確認ダイアログを出す。出題中に押した場合、その問題はそこで終わる（アナグラムですでに加点済みの正解は残す）。この操作は出題形式を問わず使える（今の「ロビーへ戻る」は順位表を出さない中断として残す）

ランダムの選び方は一様。ジャンルを一様に選んでから、その中の問題を一様に選ぶ。テストで結果を固定できるよう、乱数は外から差し替えられる形にする。

### 得意ジャンル

- ジャンル制のゲーム中（説明スライド以降、最終結果の前まで）、未選択の参加者のスマホにはジャンル一覧が出る。ちょうど 2 つ選んで「決定」
- 決定は 1 回だけ。2 回目以降・個数違い・存在しないジャンル・重複は拒否する
- 問題が尽きたジャンルは得意に選べない（残り全問を 2 倍にする抜け道をふさぐ）。残りのあるジャンルが 2 つ未満になった後に入った人は、残っているジャンルだけを選べばよい（0〜1 個で決定できる）
- 未選択の参加者の早押しは拒否する（専用のエラーコード）。途中参加も同じ
- 出題中（`question` フェーズ）に決定した人は、その問題では押せず、次の問題から押せる（ジャンルを見てから避けて申告する抜け道をふさぐ）。本人の画面には「次の問題から参加できます」と出す。説明スライド・問題結果・ジャンル選択のあいだに決定した人は、次に開く問題から押せる
- 選ぶ画面は出題中も出続ける
- 「全員が押せなくなったら自動で締め切る」の判定は、その問題で押せる接続中の参加者（得意ジャンルを選び終え、この問題の出題前に決定していた人）だけを対象にする。対象が 0 人のときは自動では締め切らない
- 得意ジャンルは公開する（ユーザーの決定）。GM 画面の参加者一覧・順位表に各自の得意ジャンルを出し、未選択の人は「未選択」と出す。管理パネルの参加者一覧にも出す。ほかの参加者のスマホには一覧としては出さない

### 得点

- 正解の加点 ＝ `basePoints` ×（その問題のジャンルが正解者の得意ジャンルに含まれなければ 2、含まれれば 1）
- 不正解の減点（`wrongPenalty`）は等倍のまま
- 実際に加えた点は今までどおり `Answer.points` に記録する。正解ポップアップと問題結果には、2 倍だったことが分かる印（「×2」）を出す
- ジャンル制でないセットの得点は変わらない

### 通信

- 参加者 → サーバー: 得意ジャンルの決定、ジャンルの指定
- GM → サーバー: ジャンルの指定（任意のジャンル／ランダム）、途中終了
- サーバー → クライアント
  - 出題の情報に、ジャンル名と「第 n 問」の n を足す
  - ジャンル選択の場面の情報: 選ぶ人、各ジャンルの残り問題数
  - 自分の情報に得意ジャンルを足す。GM 向けには全員の得意ジャンルを足す
  - セットがジャンル制のとき、ジャンル一覧（参加者が得意を選ぶため。説明スライド中から届く）
- 再接続・再読み込み時の `state` に上のすべてが入る
- 古いクライアントは、知っている `state` に新しいフェーズや項目が載っても再読み込みしない。ジャンル制のゲーム開始時に新しい type のメッセージを送り、古いクライアントを再読み込みさせる

メッセージ名や型の形は実装者に任せる。既存の命名（`startReading` / `buzzerUpdated` など）に合わせる。

### GM 画面

- **タイトルスライド**: 「早押し ・ ジャンル選択 ・ 14 ジャンル」のように出す
- **参加者一覧・順位表（右カラム）**: 各自の名前の下に得意ジャンルを小さく出す。未選択の人は「未選択」
- **出題中・問題結果**: 問題カードの上部にジャンル名を出す。読み上げ待ちのあいだは問題文が見えないので、ジャンル名が主役になる。ランダムで決まった問題には「ランダム」と添える
- **ジャンル選択**

  ```
   ○○さんがジャンルを選んでいます

   [ 動物 3 ] [ 植物 5 ] [ 海 2 ] [ 山 0 ]
   [ 昆虫 4 ] [ 天気 5 ] [ 宇宙 1 ] …

   [ランダムで決める]   [ここで終了]   [ロビーへ戻る]
  ```

  数字は残り問題数。残り 0 は押せない見た目にする。ジャンルのボタンは GM も押せる
- **フッター**: 出題中・問題結果・ジャンル選択に「ここで終了」を足す
- **管理パネル**: 参加者一覧に各自の得意ジャンルを出す

### 参加者画面

- **得意ジャンル選択**

  ```
   得意ジャンルを2つ選んでください
   （得意ジャンル以外で正解すると 2倍）

   [✓動物] [ 植物 ] [ 海 ] [ 山 ]
   [ 昆虫 ] [✓天気] [ 宇宙 ] …

          [ 決定 ]
  ```

- **出題中（早押し）**: 今の問題のジャンル名と、自分にとって「得意」か「2 倍チャンス」かを出す
- **ジャンル選択（選ぶ人）**: 「次のジャンルを選んでください」とジャンルのボタン。残り問題数、自分の得意ジャンルの印、残り 0 は押せない
- **ジャンル選択（それ以外の人）**: 「○○さんがジャンルを選んでいます」
- **問題結果**: 正解したときの加点に、2 倍だったら印を出す

### 管理画面（問題セット編集）

- 早押しの問題スライドに「ジャンル」の入力欄を足す。同じセットで使っているジャンル名を候補に出す
- 左のサムネイルにジャンル名を出す
- タイトルスライドの欄に、ジャンルごとの問題数の一覧を出す（打ち間違いで別ジャンルになったことに気づけるように）
- 保存時、ジャンルの有無が混ざっていれば、ジャンルの無い最初の問題に移動して知らせる

### テスト

既存の方針（`docs/overview.md`）に従う。少なくとも次を確かめる。

- バリデーション: 混在の拒否、3 種類未満の拒否、早押し以外で `genre` を落とすこと
- 進行: 第 1 問がランダム、正解者が選ぶ、正解者なしでランダム、尽きたジャンルの拒否、残り 1 ジャンルで選択を飛ばす、全問で最終結果、同じ問題が二度出ない
- 選ぶ人のキック・切断、GM の代理選択とランダム
- 得意ジャンル: 個数・重複・二度目の拒否、尽きたジャンルの拒否、未選択の早押し拒否、出題中に決定した人がその問題で押せず次から押せること、途中参加、自動締切の対象
- 得点: 得意は等倍、得意以外は 2 倍、減点は等倍
- 途中終了: 各フェーズから最終結果へ
- 既存: ジャンルの無い早押しとアナグラムのテストがそのまま通る
- 古いスナップショットの復元
